# 要求定義書 — mask-drift-yolo（仮）

作成日: 2026-01-24  
版: v0.1（叩き台）

---

## 1. 背景・目的

画像内の特定物体領域を **インスタンスセグメンテーション**で抽出し、その領域のみを対象にグリッド化したモザイクタイルを **Flow Field** で流すビジュアルを生成する Web アプリを作る。

- セグメンテーション推論: **YOLO セグメンテーション（ONNX Runtime Web）**
- 初期モデル: **YOLOv8/YOLO11 Seg (COCO クラス)**
- UI（パラメータ調整）: **Tweakpane**
- 表示/描画: **p5.js**
- 公開: **GitHub Pages（静的配信）**

---

## 2. ゴール（達成したい状態）

- ブラウザ上で画像を選び、Tweakpane でパラメータを設定し、RUN で以下を実行できる。
  1. 画像読み込み・前処理  
  2. セグメンテーション推論  
  3. マスク生成（複数クラスの union）  
  4. グリッド分割・セル計算（平均RGB・被覆率など）  
  5. モザイクタイルのアニメーション描画（Flow Field）
- 進行状況（例: 画像読み込み中 / 推論中 / レンダリング中 / 完了 / 中断）を UI に表示できる。
- 生成結果を Canvas に表示し、画像として保存（DL）できる（最低限 JPG）。

---

## 3. 非ゴール（今回やらない）

- 動画入力の対応（静止画のみ）
- インスタンス分離（例: 犬が2匹→右だけ選択、など）※初期は対応しない（将来拡張）
- サーバ側での推論（原則クライアント完結）
- 「flower」カテゴリの保証（VOC 系に存在しない前提。将来拡張で扱う）
- 高速化を目的としたチューニング（完成までに時間がかかってよい）

---

## 4. 対象ユーザー・利用シーン

- 画像を素材に、セグメンテーション×表現（モザイク/Flow）を試したい個人ユーザー（作者本人含む）
- 作品制作・実験用途（ツールとしての軽さと分かりやすさを優先）

---

## 5. 入力・出力

### 5.1 入力

- 画像ソース
  - サンプル画像（アプリ同梱の複数枚）
  - ユーザーのローカルファイル（画像アップロード）
- 画像形式: JPEG / PNG（最低限）
- 画像サイズ:
  - **長辺 2560px まで対応**
  - それを超える場合は、処理用に長辺 2560px へ縮小して扱ってよい（元画像は保持してもよいが必須ではない）
  - 推論入力サイズはモデル都合で 640 付近に縮小される（品質と速度のバランス）

### 5.2 出力

- p5.js Canvas 上のモザイク表現の描画結果
- ダウンロード: JPG（`S` キー）

---

## 6. 機能要件

### 6.1 UI（Tweakpane）要件

Tweakpane は **2つのパネル（または2インスタンス）**に分割して構成する。

#### 6.1.1 RUN_UI（実行/中断/状態表示）

- RUN ボタン（処理開始）
- STOP ボタン（処理中断）
- STATUS 表示エリア（文字列）
  - 例: 「待機中」「画像読み込み中…」「推論中…」「レンダリング中…」「完了」「中断」

**制御要件**
- RUN 押下後は **PARAMS_UI を操作不可（無効化）**とする。
- パラメータを変更したい場合は、ユーザーが STOP を押して処理を中断し、PARAMS_UI が再度操作可能になってから変更する。

#### 6.1.2 PARAMS_UI（入力/推論/描画パラメータ）

**A. 入力**
- Image Source: `Sample` / `Upload`
  - Sample: サンプル画像セレクト（ドロップダウン）
  - Upload: ファイル選択（input type=file 相当）

**B. セグメンテーション**
- Model: 初期は `YOLO Seg (COCO)` 固定（ただし将来の追加に備えた構造にする）
- Detect Classes: モデルが持つラベルから **複数選択**（チェックボックス群）
  - 背景（background）は選択不可、または UI 上で非表示
- Mask Strategy: **instance mask を union** してクラス単位のマスクを構成
  - 選択クラスのインスタンスを OR 合成して単一マスクにする

**C. レンダリング**
- Grid size: セルサイズ（px）
- Tile Shape: Rect / Circle
- Tile Alpha: 透明度
- Flow settings:
  - Flow Freq / Flow Twist / Flow Z Speed
  - Force / Max Speed
  - Move Frames
  - Snap To Grid / Wrap Edges

---

### 6.2 RUN 実行時のワークフロー要件

RUN 押下で以下を順に実行し、各段階で STATUS を更新する。

1. 画像読み込み・前処理（必要なら縮小）
2. セグメンテーション推論（YOLO Seg）
3. インスタンスマスクから、選択クラスの **union マスク**を生成
4. union マスクと元画像を参照し、グリッド単位でセル情報を計算
5. モザイクタイルのアニメーション描画（Flow Field）
6. 完了状態へ遷移（STATUS=完了、PARAMS_UI を再度操作可能にする）

**中断要件**
- STOP 押下で処理を中断できる。
- 中断後は STATUS=中断 とし、PARAMS_UI を操作可能に戻す。
- 中断は「現在の描画途中で止める」挙動でよい（巻き戻しや元に戻すは不要）。

---

### 6.3 セル判定ルール（マスク被覆率）

- 各セルについて「マスク被覆率」を計算し、閾値以上のセルのみをモザイク対象とする。
- **閾値: 20%（0.2）**
  - コード中で定数として管理し、後で変更しやすい形にする。
- 被覆率は厳密計算でなくてよい（セル内を一定ステップでサンプリングして近似可）。

---

### 6.4 モザイク色選択ルール

- 対象セルは **下地画像の平均RGB** を取得してタイル色に反映する。
- 任意でアルファ（Tile Alpha）を下げられるようにする。

---

### 6.5 描画制御（クラス設計方針）

- グリッドセルを `MosaicCell` クラスとして表現し、セル単位で描画内容を制御する。
- セル生成は「分割実行」を前提とし、アニメーションは Flow Field による移動で表現する。
- リアルタイム性は要求しない。完成まで時間がかかってよい。

---

## 7. 非機能要件

### 7.1 性能・体感

- 静止画特化。推論/描画に数秒〜十数秒かかっても許容。
- ただし「固まって見える」状態は避けるため、STATUS は必ず更新される。
- マスク生成など高コスト処理は、必要最小限の回数に抑える（毎フレーム推論しない）。

### 7.2 動作環境

- PC ブラウザを主対象（最低限 Chrome を優先対応）
- モバイル対応は非必須

### 7.3 セキュリティ・プライバシ / 公開

- 入力画像は原則ローカル処理（サーバへ送らない）
- 公開は **GitHub Pages** を想定（静的ファイル配信）

### 7.4 将来拡張性

- セグメンテーションモデルは差し替え可能な構造を前提とする。
  - モデルごとに「ラベル一覧」「推論方式（category/confidence）」などを持てる設計を想定。
- 将来、VOC 以外（より多クラス / flower を含む、など）のモデル追加を可能にする。

---

## 8. 初期対応クラス（YOLO Seg / COCO）

初期は **COCO 80クラス**を候補として UI に表示する（背景は除外）。
（UIには一覧を表示し、検索/フィルタは将来対応）

---

## 9. 受け入れ基準（Acceptance Criteria）

- [ ] サンプル画像/アップロード画像の両方で動作する
- [ ] クラス複数選択で union マスクが反映される（例: dog + chair + bus）
- [ ] RUN で「推論→レンダリング」まで完走し、Canvas にモザイク結果が表示される
- [ ] RUN 中は PARAMS_UI が操作不可になり、STOP または完了で操作可能に戻る
- [ ] STATUS が段階的に更新され、処理中であることが分かる
- [ ] 結果を JPG として保存できる（`S` キー）

---

## 10. 既知の制約・注意

- YOLO Seg は **instance segmentation** だが、初期実装ではインスタンス分離UIは持たない。
- マスク解像度と表示解像度が一致しない可能性があるため、座標合わせ（リサンプル or サンプリング）が必要。
- モデルサイズ/実行環境（WASM/WGPU）によって推論時間が伸びる（許容）。
